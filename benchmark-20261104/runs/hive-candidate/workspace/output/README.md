# Hive browser → CLI worker → team

This diagram describes the local **CLI-orchestrator** path at clean revision `f8f1343da6595a232f0baba7f0ea5b5a58fe0e9c` of `https://github.com/tt-a1i/hive`. Sources are repository-relative and retained in `candidate.json` and the diagram's clickable component passports. Both application and Archify source remain unchanged.

## Reading the implementation

1. **The active UI path is a terminal, not a browser-hosted agent.** xterm input calls `client.sendInput`, and the terminal client opens `/ws/terminal/:runId/io` plus `/control` (`web/src/terminal/useTerminalRun.ts:593–647`; `web/src/terminal/terminal-client.ts:99–109`). The runtime routes input to `store.writeRunInput` (`src/server/terminal-stream-hub.ts:301–316`). `agent-manager` spawns a configured CLI with the PTY adapter and writes to its process (`src/server/agent-manager.ts:153–178`; `src/server/pty.ts:1–9`).
2. **The orchestrator chooses to delegate.** The bundled `team send` command POSTs the worker name and task to `/api/team/send` (`src/cli/team.ts:1255–1268`). `team` targets `http://127.0.0.1:${HIVE_PORT}` (`src/cli/team.ts:105`). The CLI receives workspace/agent identity and a PATH prepend at bootstrap, then the actual port and token at startup (`src/server/agent-run-bootstrap.ts:127–138`; `src/server/agent-run-starter.ts:112–125`). This is a CLI decision guided by `src/server/hive-team-guidance.ts:24–43`, not a deterministic runtime scheduler turning every browser input into a worker task.
3. **The runtime owns dispatch state and transport.** The route checks token, workspace membership and role (`src/server/routes-team.ts:127–151`; `src/server/team-authz.ts:75–100`). `team-operations` logs the send, creates a dispatch, claims it and calls `writeSendPrompt` (`src/server/team-operations.ts:604–685`). User-managed stopped workers remain queued until restarted; limited auto-start paths exist (`src/server/routes-team.ts:145–170`; `src/server/team-operations.ts:648–667`). Dispatches are sent as prompt envelopes with their dispatch ID; writes are serialized per agent and use the interactive input writer (`src/server/agent-stdin-dispatcher.ts:125–210,245–265,286–344`).
4. **There are three different progress channels.** Raw PTY output is published on the output bus (`src/server/agent-manager-support.ts:338–343`) and streamed to browser viewers (`src/server/terminal-stream-hub.ts:145–158`), with flow-control and restore handling. Task-bound `team message --kind progress --to orchestrator` is stored but gets no delivery-outbox entry, so it does not wake the orchestrator (`src/server/hive-team-guidance.ts:50–54`; `src/server/dispatch-message-store.ts:160–206`). It remains available through task-message reads (`src/server/routes-team-messages.ts:73–91`; `src/server/routes-dispatches.ts:35–95`). Optional `team status` logs and forwards a status prompt without closing a responsibility (`src/server/team-operations.ts:916–972`).
5. **Completion is an explicit protocol action.** The worker runs `team report`, submitting text, artifact path strings, dispatch ID and optional `seen_seq` (`src/cli/team.ts:1558–1574`). The authenticated route invokes `reportTask` with `requireActiveRun: true` (`src/server/routes-team.ts:397–444`). The ledger rejects missing open work or a stale acknowledgement of inbound messages (`src/server/dispatch-ledger-store.ts:340–375`). A committed report stores the message, updates the dispatch to `reported`, enqueues the orchestrator payload, and decreases worker pending work (`src/server/team-operations.ts:978–1069`). This settles a responsibility even when its outcome is partial or failed; it is not proof of successful implementation.
6. **The result returns through two independent surfaces.** The report outbox injects a system envelope into the orchestrator's stdin and marks it delivered only after the write resolves (`src/server/team-operations.ts:294–335,1113–1132`). A down orchestrator leaves the result queued; `team list`/start hooks can retry. Delivery can be repeated across failure boundaries, so the envelope explicitly tells the orchestrator to deduplicate by dispatch ID (`src/server/agent-stdin-dispatcher.ts:29–53`). The browser separately polls reported dispatches approximately every two seconds and raises report notifications (`web/src/notifications/useReportNotifications.ts:36–95`; `web/src/api.ts:2161–2183`). It also displays the orchestrator's subsequent terminal output.

## Scope and uncertainty

- The diagram groups the terminal WebSocket hub, stdin dispatcher and PTY manager as one runtime subsystem; team routes, team operations and their store adapters form the other. These are code responsibilities inside one Node.js runtime, **not additional services**. SQLite is persistent protocol state; live PTY processes and their queues are separate memory/process state.
- An HTTP user-goal entry also exists (`src/server/routes-workspaces.ts:169–196`; `web/src/api.ts:315–324`), but a search of the checked-out web source found no caller of `sendWorkspaceUserInput`. It is therefore not asserted as the active browser entry.
- `.hive/tasks.md` is a separate task-planning file (`src/server/tasks-file.ts:25–31`), not the dispatch transport. This overview does not assert that editing a checkbox schedules a worker, or that `team report` automatically edits that file.
- Local UI entry validates a UI token; CLI routes validate agent tokens and workspace membership. These are application checks, not evidence of OS sandboxing. CLI execution and local HTTP are separate process/communication boundaries on the same host.
- No agent CLI was launched and no model/live service was contacted. Hive's source establishes how prompts and reports are transported, not the third-party CLI's internal reasoning, model-provider traffic, eventual success, or guaranteed orchestrator consumption of a report. An HTTP 202 is acceptance; a resolved PTY write is not an agent-level acknowledgement.
- Remote gateway/tunnel, the optional workflow runner and the external Codex App controller are intentionally outside this local path. In particular, workflow dispatches notify an in-process awaiter rather than the orchestrator PTY (`src/server/team-operations.ts:1076–1099`); controller-mode report/status adaptation exists in `src/server/runtime-store-controller.ts:217–237`.

## Simplification review

After the first browser review, a redundant round-trip summary card was removed: the numbered connections already carry that journey, and the remaining two cards explain non-obvious protocol semantics. The diagram still retains all components, relationships and source references. Helper-by-helper nodes, optional workflows, remote services, model providers and task-file watchers are omitted. Removing the separate orchestrator, worker, persistent state, or either runtime subsystem would conceal a requested control, process, persistence or communication distinction, so those remain. One worker represents the repeatable worker path; no particular team size is implied.
