# Hive task-to-worker path — source notes

Snapshot: `f8f1343da6595a232f0baba7f0ea5b5a58fe0e9c` of the selected Hive checkout; clean at inspection. Diagram components retain clickable local source ranges. Paths below are relative to `project/`.

## Reading the diagram

1. A user types a goal in a workbench terminal. The browser opens per-run I/O and control WebSockets (`web/src/terminal/terminal-client.ts:99–110`). The stream hub normalizes input and calls `store.writeRunInput` (`src/server/terminal-stream-hub.ts:301–316`). The PTY process write is in `src/server/agent-manager-support.ts:330–334`.
2. The orchestrator CLI chooses a member and invokes `team send`. The helper posts JSON to the loopback Hive runtime (`src/cli/team.ts:105`, `1254–1268`). The server authenticates agent identity/token, checks the role and calls dispatch operations (`src/server/routes-team.ts:127–152`; `src/server/team-authz.ts:75–100`). No browser-to-worker job broker is implied.
3. Team operations create a dispatch, optionally start an eligible worker, and write its prompt (`src/server/team-operations.ts:604–738`). The dispatch envelope carries task and dispatch identity (`src/server/agent-stdin-dispatcher.ts:286–339`). `agentManager.startAgent` spawns the configured command in a PTY (`src/server/agent-manager.ts:153–166`). Startup passes cwd and Hive environment/token (`src/server/agent-run-starter.ts:112–143`; `src/server/agent-run-bootstrap.ts:127–138`). The diagram's “PTY dispatch prompt” means a server-runtime write, not a direct API-to-process network connection.
4. Raw output returns through PTY `onData` → output bus (`src/server/agent-manager-support.ts:338–343`) → stream-hub viewers (`src/server/terminal-stream-hub.ts:146–158`) → browser output handler (`web/src/terminal/terminal-client.ts:172–180`). This is live visibility, not proof of task completion.
5. Structured progress is `team message --dispatch <id> --to orchestrator --kind progress "..."` (`src/cli/team.ts:308`, `1223–1249`). `/api/team/message` authenticates and validates it (`src/server/routes-team-messages.ts:34–71`); operations persist the message and drain an outbox (`src/server/dispatch-message-operations.ts:70–95`). Delivery waits for an active recipient and writes an envelope into its PTY; failure requeues for a later explicit drain/start (`src/server/dispatch-message-outbox.ts:34–61`).
6. `team report` terminates a responsibility. The route requires worker-role permission and calls `reportTask` with `requireActiveRun: true` (`src/server/routes-team.ts:394–447`). Operations locate an open dispatch, record the report, enqueue an orchestrator envelope and mark the dispatch reported in a mutation (`src/server/team-operations.ts:978–1049`). Worker pending-task state is updated after commit (`1064–1074`). The worker stays working if other dispatches remain; a report is not the worker process exiting.
7. A recorded report can still be awaiting delivery. The outbox is marked delivered only after the runtime's PTY write resolves (`src/server/team-operations.ts:293–323`). An offline orchestrator leaves a queued report (`1113–1132`); `team list` or a fresh report can trigger retry (`293–297`). Progress and report writes target the orchestrator; teammates may exchange allowed dispatch-scoped messages rather than receiving an invented broadcast.
8. The browser also gets structured state through UI APIs. Action Center polls every two seconds (`web/src/action-center/ActionCenterStrip.tsx:32`, `120–165`), uses the authenticated summary endpoint (`src/server/routes-action-center.ts:9–28`), and shows activity/report excerpts derived from dispatch state (`src/server/action-center-summary.ts`). Recap reads recent dispatch records (`src/server/routes-action-center.ts:30–53`). The lower return arrow abbreviates HTTP request + response; its arrowhead denotes returned data.

## Important distinctions and uncertainty

- **Task document is not dispatch:** `.hive/tasks.md` is the task document (`src/server/tasks-file.ts:24–34`). Its browser GET/PUT routes read/write content, not call dispatch (`src/server/routes-tasks.ts:40–79`). `team next` computes runnable candidates, not automatic execution (`src/server/routes-tasks.ts:8–37`). The tasks watcher/WebSocket keeps that document view current; it is not the worker result channel shown here.
- **Alternative input endpoint:** `/api/workspaces/:workspaceId/user-input` is implemented and requires an active orchestrator (`src/server/routes-workspaces.ts:169–196`); its browser API helper exists (`web/src/api.ts:315–324`), but no caller was found in this checkout. The diagram therefore uses the evidenced interactive terminal path rather than presenting this helper as the normal UI entry.
- **Stopped workers:** user-managed stopped workers are queued, not unconditionally auto-started. A never-started orchestrator-spawned member may be woken on its first send (`src/server/routes-team.ts:145–169`). Queued work is replayed on start (`src/server/team-operations.ts:661–666`).
- **Persistence boundary:** dispatches and outboxes are SQLite state, not an external messaging service. Local database opening is in `src/server/runtime-database.ts:128–144`; ledger SQL writes are in `src/server/dispatch-ledger-store.ts:177`, `231–281`, `361–405`. `--artifact` values are path references; this path does not establish artifact upload or external storage.
- **Agent behavior is not guaranteed:** the code establishes prompts, commands and transport, not that an arbitrary CLI agent will always choose a worker, emit progress, report correctly or summarize the result. Natural-language planning and tool compliance are outside deterministic server control.
- **Deliberate scope:** local browser/team/CLI path only. Optional workflow runner promises, external controllers, remote gateways, memory injection and provider internals are not required for this path and are omitted. The two server boxes are cooperating modules in one Hive runtime, not separately deployed services.

## Simplification review

The overview omits individual route handlers, separate helper CLI processes, the report and message outbox implementations, and the task-file watcher as standalone boxes. Removing those boxes preserves the requested control ownership, process/persistence boundaries and both return channels. Removing the orchestrator, worker, PTY transport, collaboration authority or persistent outbox distinction would hide essential behavior, so those remain.
