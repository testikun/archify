# Hive workbench task round trip

Source checkout: `../project`, clean at `f8f1343da6595a232f0baba7f0ea5b5a58fe0e9c` (origin `https://github.com/tt-a1i/hive`). The HTML's component passports retain revision-pinned source links. This companion records additional evidence behind the overview grouping.

## Actual entry and execution path

1. The browser's xterm `onData` calls the terminal client's `sendInput`; received output is enqueued for rendering (`web/src/terminal/useTerminalRun.ts:593–646`). The client opens `/ws/terminal/:runId/io` and `/control` (`web/src/terminal/terminal-client.ts:90–109`). The server validates local access / UI session on upgrade (`src/server/terminal-ws-server.ts:60–65, 86–118`). The stream hub writes accepted input to `store.writeRunInput` (`src/server/terminal-stream-hub.ts:301–316`). This path is terminal interaction, not browser-side automatic assignment.
2. Hive instructs the orchestrator CLI to run `team send "<member-name>" "<task>"` for new responsibility (`src/server/hive-team-guidance.ts:23–33`). The helper POSTs `/api/team/send` with agent/workspace/token context (`src/cli/team.ts:1255–1268`); its base URL is loopback HTTP using `HIVE_PORT` (`src/cli/team.ts:105`). Agents are token-checked and commands are role-restricted (`src/server/team-authz.ts:27–64, 75–100`; send route: `src/server/routes-team.ts:127–170`).
3. Dispatch operations insert a send message and create a dispatch before delivery (`src/server/team-operations.ts:604–645`). The route intentionally parks work for a user-managed stopped worker; an orchestrator-spawned never-started member is the first-send exception (`src/server/routes-team.ts:145–169`). The runtime waits for post-start readiness, atomically claims `queued → submitted`, and calls `writeSendPrompt` (`src/server/team-operations.ts:648–785`). Runtime startup drains old reports, replays parked dispatches and drains dispatch-message delivery (`src/server/runtime-store-helpers.ts:510–534`). A PTY write completion is not an acknowledgement that the agent understood the task (`src/server/team-operations.ts:246–266`).
4. CLI startup supplies cwd and endpoint/token environment and calls AgentManager (`src/server/agent-run-starter.ts:104–143`). AgentManager spawns the configured command under a PTY and writes via the PTY process (`src/server/agent-manager.ts:125–178`; native PTY selection: `src/server/pty.ts:1–9`). Stdin injection waits for readiness and re-resolves the active run before writing (`src/server/agent-stdin-dispatcher.ts:164–209`); task payload construction and queued delivery are in `src/server/agent-stdin-dispatcher.ts:286–354`.

## Three different kinds of progress/result

- **Terminal visibility:** PTY `onData` publishes chunks to the output bus (`src/server/agent-manager-support.ts:338–343`). The hub mirrors and fans chunks to viewers (`src/server/terminal-stream-hub.ts:145–158`); the browser renders them. Neither bytes nor process output certify a completed responsibility.
- **Task-bound progress:** `team message --dispatch <id> --to orchestrator --kind progress` is the instructed routine progress mechanism (`src/server/hive-team-guidance.ts:45–54`). The helper calls `/api/team/message` (`src/cli/team.ts:1241–1249`); the route authenticates, authorizes and saves through `sendDispatchMessage` (`src/server/routes-team-messages.ts:35–71`). The store deliberately skips outbox creation for `progress` (`src/server/dispatch-message-store.ts:160–206`), so progress does not wake the orchestrator. It remains queryable with `team messages` (`src/server/routes-team-messages.ts:73–91`) and in UI collaboration history (`src/server/routes-dispatches.ts:35–100`). This is distinct from dispatching another task.
- **Attention/status:** `team status` calls `/api/team/status` (`src/cli/team.ts:1538–1553`; authentication and role check: `src/server/routes-team.ts:449–474`). It logs and injects a status payload into the orchestrator, without closing the dispatch (`src/server/team-operations.ts:916–977`; target PTY: `src/server/agent-stdin-dispatcher.ts:276–284`). Forwarding can fail; it is not the durable report-outbox path.
- **Result:** `team report` POSTs result text, artifact references, dispatch ID and optional seen sequence (`src/cli/team.ts:1557–1574`; route: `src/server/routes-team.ts:397–447`). The ledger requires the worker's submitted dispatch (or an unambiguous submitted dispatch if no ID), and an exact required seen sequence (`src/server/dispatch-ledger-store.ts:294–385`). The operations atomically insert the report log, queue the orchestrator payload, and mark the dispatch reported (`src/server/team-operations.ts:978–1045`; transaction wiring: `src/server/runtime-store-helpers.ts:414–439`). Result persistence and delivery are separate: outbox draining marks delivered only after the PTY write resolves (`src/server/team-operations.ts:296–350`); a down orchestrator leaves the result queued (`src/server/team-operations.ts:1113–1132`). On restart backlog drains (`src/server/runtime-store-helpers.ts:510–534`). The agent's subsequent synthesis is terminal output visible in the browser, not a guaranteed automatic interpretation of the report.

## Persistence, scope and uncertainty

Stores share the runtime's SQLite database (`src/server/runtime-store-helpers.ts:161–175`). With a data directory it is `runtime.sqlite`; without one it is in-memory (`src/server/runtime-database.ts:129–149`). The diagram shows persistence responsibility separately from the Node.js control process, not an independent network database service.

The diagram intentionally follows local workbench terminals and CLI-team dispatch. It does not expand remote tunnels, optional workflow-runner dispatch, or the alternative Codex App controller. A separate HTTP user-input endpoint/helper exists (`web/src/api.ts:315–324`; `src/server/routes-workspaces.ts:169–192`), but no call site for that exported helper was found in the browser source; it is not promoted into the primary path. External CLI behavior, model/backend execution and correctness of results are not established by Hive's transport code. No live Hive services or external model calls were run.

## Simplification check

The diagram intentionally groups AgentManager, stdin dispatch and terminal streaming into one runtime component, with their distinct roles and references retained in its passport. Splitting them into service-looking boxes would imply boundaries that do not exist and obscure the round trip. As an actual simplification experiment, the redundant single-node “Separate CLI process” frames were removed and the complete Archify gates rerun. The retained Hive Node.js frame, explicit CLI-process labels outside it, and distinct SQLite node still expose the required boundaries. Removing either CLI process, the team protocol, or the SQLite responsibility would hide a required execution, authorization, or durability boundary; those remain. The separate progress/status/report paths are kept in the cards because merging them into a generic “progress stream” would be false.
